# Multi-Program Support (Lightning + Warriors)

**Date:** 2026-07-20
**Status:** Approved

## Goal

Serve multiple basketball programs (Lightning today, Warriors next) from this one
codebase. Each program has its own Google Sheet, domain, branding (name, icons,
colors), and output directory — but shares all generation logic, templates, and
deploy machinery.

## Background

Today all program-specific values are hardcoded:

- `generate.go:22-27` — `domain` constant, Google Sheet ID, and per-tab CSV URLs (gids)
- `generate.go` — "Lightning" page title fallback, iCal `PRODID`, `X-WR-CALNAME`
- `templates/schedule.css` — Lightning gold accent (`#fbcb44`) and per-team color
  classes (`10ublack`, `10ured`, `12ublue`, `14ugold`, `14uwhite`, `jv`, `varsity`, …)
- `templates/icon.png`, `templates/favicon.png` — source branding images
- `static/manifest.json` — PWA name, short name, theme color
- `deploy.sh` — web directory named after the Lightning domain

The Warriors Google Sheet will be a copy of the Lightning sheet: identical tabs
(Schedule, Notes, Locations, Teams) and identical columns. Only the sheet ID and
tab gids differ. Warriors deploys to its own domain on the same server (host `dh`).

## Design

### Program config directory

```
programs/
  lightning/
    config.json      # name, domain, sheet ID, tab gids, theme color, iCal names
    theme.css        # accent color + team color classes for this program
    icon.png         # source image for touch/chrome icons
    favicon.png      # source image for favicons
  warriors/
    (same files, Warriors values)
```

`config.json` shape:

```json
{
  "name": "Lightning",
  "domain": "schedule.omahalightningbasketball.com",
  "sheetID": "1JG0KliyzTT8muoDPAhTJWBilE1iUQMm22XOq1H4N6aQ",
  "gids": { "schedule": "0", "notes": "436458989", "locations": "1311642203", "teams": "440511811" },
  "themeColor": "#fbcb44",
  "icalProdID": "-//Omaha Lightning//Basketball Schedule//EN",
  "icalCalName": "Lightning Schedule"
}
```

### generate.go changes

- A `ProgramConfig` struct replaces the package-level constants. CSV URLs are
  built from `sheetID` + `gids`.
- The whole `programs/` tree is embedded via `//go:embed programs` so the
  deployed artifact stays a single self-contained binary (it runs remotely on a
  cron via `deploy.sh`).
- Program selection: `-program <name>` flag, default `lightning`, so existing
  invocations keep working. Output dir remains an optional positional arg.
- Page title, iCal `PRODID`, and `X-WR-CALNAME` come from the config.

### CSS theming

- `templates/schedule.css` keeps layout and shared styles only.
- The accent color and team color classes move to each program's `theme.css`.
- At generate time the program's `theme.css` is appended after the base CSS and
  inlined into the page exactly as today.

### Icons and manifest

- `build.sh` loops over `programs/*/`, generating the icon size variants from
  each program's `icon.png`/`favicon.png` into `static/<program>/`.
- `manifest.json` becomes a per-program file in `static/<program>/`, templated
  from the config's name and theme color (generated by `build.sh`).
- `static/<program>/` files stay committed to git, matching how the generated
  `static/` assets are handled today.

### Output layout

- Local: `go run generate.go -program lightning` writes to `dist/lightning/`;
  `-program warriors` writes to `dist/warriors/`. Both programs live under
  `dist/<program>/` for consistency (Lightning moves out of `dist/` root).
- Remote: unchanged model — the binary runs on the server with the program's
  web dir as the output arg.

### Deploy

- `deploy.sh` gains a per-program config block mapping program name → web dir:
  - `lightning` → `~/schedule.omahalightningbasketball.com`
  - `warriors` → `~/schedule.<warriors-domain>` (filled in when the domain exists)
- It uploads one binary, then for each program: uploads `static/<program>/*` to
  that program's web dir and runs the binary remotely with
  `-program <name> <web dir>`.
- Optional: `deploy.sh [program]` deploys just one program; no arg deploys all.

## Error handling

- Unknown `-program` value: exit with an error listing available programs
  (discovered from the embedded `programs/` tree).
- Missing/invalid `config.json`: fail fast at startup with a clear message.
- Fetch behavior per sheet is unchanged (teams fetch is fatal, locations/notes
  degrade to empty).

## Testing

- `go run generate.go` (defaults to lightning) and inspect `dist/lightning/`
  output per CLAUDE.md. Compare against pre-refactor output — HTML should be
  byte-identical apart from the moved directory and timestamps.
- Once the Warriors sheet exists: `go run generate.go -program warriors` and
  inspect `dist/warriors/`.

## Out of scope

- Any change to sheet structure or parsing.
- Cross-program index page or shared landing page.
- Warriors sheet/domain creation (happens outside this repo).
